# stays local

**A badge for apps that never phone home — earned by a check anyone can rerun.**

Plenty of apps say they work locally. Nothing checks. `stays local` is the check: your source is built in this repository's CI, the artifact is scanned for any way to reach the network, and the app is run and watched. Pass, and you get a badge generated by the run that earned it.

## Platforms

| Platform | Spec | Verifier | Evidence it rests on |
|---|---|---|---|
| **macOS** | [stable](spec/macos.md) | [done](verifiers/macos/verify.sh) | Nothing in the bundle links `CFNetwork` |
| **Android** | [draft](spec/android.md) | [wanted](https://github.com/2JIHAN/stays-local/labels/verifier) | The OS refuses sockets without `INTERNET` |
| **Windows** | [draft](spec/windows.md) | [wanted](https://github.com/2JIHAN/stays-local/labels/verifier) | No PE imports `WS2_32`, `WINHTTP`, … |
| **iOS** | [draft](spec/ios.md) | [wanted](https://github.com/2JIHAN/stays-local/labels/verifier) | Symbol references — linkage proves little here |

Platforms are not interchangeable, and the badge should not pretend otherwise. Android's badge is the strongest available: without the `INTERNET` permission the kernel refuses the socket, so the property is *enforced* rather than inferred. macOS is inferred from linkage. iOS is the weakest, because `UIKit` drags `CFNetwork` in on every app and the linkage check loses its teeth.

## What passing means

**The app's shipped code contains no way to reach the network.** That is the whole claim, and it is narrow on purpose, because it is the part that can actually be checked.

Each platform defines its own layers; see its spec. Layers are `required` (failing fails the badge) or `recorded` (published, but does not decide the verdict — usually because it cannot run everywhere).

## What it does not mean

| Not covered | Why |
|---|---|
| Code the app shells out to | `curl` in a script is invisible to a binary scan |
| IPC to another process | The app can ask a service that does have network access |
| Files written for another app to upload | Nothing leaves *this* process; something else may carry it |
| Code loaded at runtime | A plugin is not in the artifact we checked |
| **Data smuggled in a declared URL** | Unsolved. See [known gaps](spec/core.md#known-gaps) |
| The binary you downloaded | We check a build from public source, not your download |

It is one checkable property, not a privacy audit. Say so when you cite it. [`bypasses/`](bypasses/) is the public catalogue of ways around it.

## Apply

1. Add `stays-local.json` to your repository root:

```json
{
  "name": "Your App",
  "platform": "macos",
  "repository": "https://github.com/you/your-app",
  "build": "./build.sh \"$STAYS_LOCAL_OUT\"",
  "bundle": "Your App.app",
  "declared_urls": []
}
```

2. Run the check yourself first:

```bash
git clone https://github.com/2JIHAN/stays-local.git
./stays-local/verify.sh /path/to/your-repo --runtime
```

3. [Open an application issue](https://github.com/2JIHAN/stays-local/issues/new?template=apply.yml).

The check then runs here, on a fresh checkout of your public source, and the log is public. You do not certify yourself, and no maintainer can wave you through — [the run decides](GOVERNANCE.md#certification-is-not-a-judgement-call).

## Use the badge

Your badge is generated by the run that certified you and lives here, so it is not a picture you host and control.

```markdown
[![stays local](https://raw.githubusercontent.com/2JIHAN/stays-local/main/badges/YOUR-SLUG.svg)](https://github.com/2JIHAN/stays-local#registry)
```

`registry/YOUR-SLUG.json` holds the same result in machine-readable form, including which layers passed and a link to the run.

## Contributing

**Three platforms need a verifier.** That is where the work is, and landing one makes you its maintainer. Android is the most valuable, because it is the only platform where the OS enforces the property instead of us inferring it.

**Bypasses are the other half.** [`bypasses/`](bypasses/) is a corpus of apps that reach the network while passing layers. Adding a case that current verifiers miss is arguably a better contribution than a feature — it is the thing that keeps the badge from becoming decoration.

Read [CONTRIBUTING.md](CONTRIBUTING.md). Criteria changes carry a higher bar than code changes, because they change what every existing badge means, retroactively — that split is written down in [GOVERNANCE.md](GOVERNANCE.md).

If you have a working bypass, read [SECURITY.md](SECURITY.md) before opening it in public. Every certified app is affected until it is fixed.

## Staying honest

Entries are re-verified weekly against the default branch. An entry that stops passing has its badge regenerated as `failed` — the badge you embed is the one this repository generates, so it cannot go on claiming something that stopped being true.

Closed-source apps cannot be certified. The check needs to build from public source, and a claim you cannot inspect is the thing this is meant to replace.
