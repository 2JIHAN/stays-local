stays local

A badge for apps that never phone home — earned by a check that runs in public CI on your source, not on the author's machine.

Repository Read the spec Apply

Plenty of apps say they work locally. Nothing checks. This is the check.

Your source is built in this repository's CI, every binary in the artifact is scanned for any way to reach the network, and the app is run and watched. Pass, and you get a badge generated by the run that earned it — a badge you do not host and cannot edit.

It carries the date it was earned, so a claim about software shows its age instead of implying it is checked forever.

Platforms

PlatformStatusWhat the badge rests on
Androidcertifying appsThe OS refuses sockets without INTERNET
macOScertifying appsNo binary in the bundle names URLSession, sockets, …
Windowsspec drafted, verifier wantedNo PE imports WS2_32, WINHTTP, …
iOSspec drafted, verifier wantedSymbol references — linkage proves little here

The badges are not interchangeable and the spec says so. Android's is the strongest available: without the INTERNET permission the kernel refuses the socket, so the property is enforced rather than inferred. macOS is inferred from the symbols a binary names. iOS is the weakest, because UIKit drags CFNetwork into every app and the linkage check loses its teeth.

What passing means

The app's shipped code contains no way to reach the network. That is the whole claim. It is narrow on purpose, because it is the part that can actually be checked.

What it does not mean

Not coveredWhy
Code the app shells out tocurl in a script is invisible to a binary scan
IPC to another processThe app can ask a service that does have network access
Files another app uploadsNothing leaves this process; something else may carry it
Code loaded at runtimeA plugin is not in the artifact we checked
Data smuggled in a declared URLUnsolved — see the known gaps
The binary you downloadedWe check a build from public source, not your download
It is one checkable property, not a privacy audit. The bypass corpus is a public, executable catalogue of ways around it, and CI runs it on every push — a verifier that stops catching one goes red.

Apply

Add a manifest to your repository root:

{
  "name": "Your App",
  "platform": "macos",
  "repository": "https://github.com/you/your-app",
  "build": "./build.sh \"$STAYS_LOCAL_OUT\"",
  "bundle": "Your App.app",
  "declared_urls": []
}

Run the check yourself first, then open an application issue:

git clone https://github.com/2JIHAN/stays-local.git
./stays-local/verify.sh /path/to/your-repo --runtime

The check then runs here, on a fresh checkout of your public source, and the log is public. You do not certify yourself, and no maintainer can wave you through — the run decides.

Help wanted

Only macOS and Android can be certified today. Windows and iOS have a written spec and no verifier, so there is nothing to earn a badge from yet.

Contributions are welcome and those two platforms are wide open. There is nothing to reverse-engineer: the layers are described, the open design questions are listed, and you are expected to argue with them before writing anything. Neither is certifying apps yet, so nothing depends on getting it right the first time — which is the easiest a project of this kind will ever be to join. Landing a verifier makes you that platform's maintainer.
